# 验收报告格式（第 7 步，草案）

对应 DESIGN.md 流程第 6 步"交付"与实现顺序第 7 步。桌面报告模板已完成界面核对；正式报告生成命令、任务绑定和公差分析仍未实现。正式实现沿用设计计划页面的做法（[interview-and-plan.md](./interview-and-plan.md)）：本地单文件 HTML、只读、版本化、内容可校验。

用户已明确报告用于桌面 Zemax 工作流，本阶段以桌面浏览器和打印为验收范围，不把手机、窄屏或手机横屏适配作为交付条件。

## 1. 什么时候生成

设计任务停机后生成，一个任务一份当前报告，旧版本保留。停机状态与报告类型：

| 状态 | 触发 | 报告类型 |
|---|---|---|
| 通过 | 某轮 G = 0 | 验收报告 |
| 未通过：停滞 | 停机规则判停滞 | 差距报告 |
| 未通过：达到轮次上限 | 达到上限仍 G > 0 | 差距报告 |
| 无法评估 | 最好一轮仍为 invalid（G = ∞） | 差距报告，原因写评估失败的环节（光线追迹、调焦、拟合残差） |
| 未验收：超出第一版范围 | 访谈中有第一版验收器不能评价的要求，没有可确认的设计计划 | 范围说明（第 7 节），不是验收报告 |

交付的镜头：通过时取第一个通过的轮次；未通过时取 G 最小的轮次，相同时取较早者。不把评价函数值最小、或 agent 认为"看起来更好"的轮次作为交付。

停滞阈值和轮次上限目前未校准（[step5-calibration.md](./step5-calibration.md)）。停机原因是停滞或上限时，报告必须写出这一点，以及当时使用的参数。

## 2. 输入与绑定

报告只读取已有记录，不重新计算任何判定：

- 已确认的设计计划版本（`plan/<SHA-256>/`）：用户原话、完整规格、假设、期望项、初始结构；
- 冻结的验收配置及哈希（`spec/frozen_config.json`）；
- `rounds.jsonl` 与交付轮次的验收结果 `eval/rNNN.accept.json`；
- 交付轮次的镜头文件 `lenses/rounds/rNNN.zmx` 与验收模型 `eval/rNNN.accept.zmx`；
- 运行信息：OpticStudio 版本、运行模式（必须是 standalone，窗口实例的结果不进入报告）、代码版本。

生成前核对：交付轮次的配置哈希等于冻结值；计划确认绑定的规格与冻结配置一致；镜头文件哈希与轮次记录时一致。任何一项不符就拒绝生成，并给出原因。

产出放在任务的 `report/<完整版本 SHA-256>/`：`index.html`、`report.json`（全部数值的机器可读版本）、`figures/`（剖面 PNG 与各分析的数值 JSON）、`files.sha256`（所列交付文件的校验值）。

## 3. 页面结构（自上而下）

1. **结论栏**：状态（第 1 节五种之一）、规格差距 G、停机原因与轮次、交付文件名；一句白话说明，只陈述程序结论。停机原因是停滞或上限时注明停机参数未校准。
2. **图形**（见第 4 节）：一行几何参数、两个图形面板、玻璃图例。
3. **用户需求**：用户原话、已确认计划的版本号和确认原话。
4. **逐项结果表**：每个约束和性能指标一行——名称、类别、达标线、实测值（带单位）、单项差距、是否通过、一句白话含义。未通过的排在前面。
5. **差距**（仅未通过时）：每个未通过项的超出量（原单位和归一化）、各轮最好值及所在轮次、最后几轮的走势；固定写明程序没有放宽任何规格。
6. **agent 的解释**（版式上与程序结论分开，标"解释，不是判定"）：可能原因与可尝试的方向；不得出现改变结论的说法。
7. **假设**：计划中每一条补全的规格及依据，标出影响了哪些判定项。
8. **期望项**、**诊断量**：注明不参与判定。按系统用途跳过的诊断量也要列出：写明未计算、跳过的理由，并说明可以按同一验收焦面补算。第一版的显微物镜不跳过任何诊断量（消色差规格下的平场比照常计算）。
9. **调整轮次**：G 随轮次的折线（G = ∞ 的轮次单独标出），逐轮记录可展开。
10. **验收口径**：谱线、视场采样、验收焦面、判据出处、冻结配置哈希、运行环境。
11. **适用范围与已知限制**、**交付物清单**（含 SHA-256）、**后续**（公差分析提示）。

## 4. 图形

参照 DeepO（ai4optics.com/deepo）的双面板形式：左右两个面板，各自用标签页切换图形。标签页用单选按钮与 CSS 实现，不使用脚本；桌面使用左侧章节大纲，正文包含图形、逐项结果和差距；打印时隐藏大纲、展开全部图形和逐轮记录。

| 位置 | 标签页 | 来源 |
|---|---|---|
| 面板上方 | 一行几何参数：主波长、NA、焦距、放大率与筒镜焦距、物方视场直径、工作距离、光学长度、通光直径、片数；下方玻璃图例 | agent 按本任务的规格选择要列的量，数值取自验收结果；不单独占一节 |
| 左面板 | 剖面 | **Zemax 原生导出**：`Tools.Layouts.OpenCrossSectionExport()` 的 `SaveImageAsFile` 输出 PNG |
| 左面板 | 点列图、光线扇形图 | Zemax 计算（点列为批量光线追迹的落点，扇形图为 RayFan 分析的数据序列），报告绘制 |
| 右面板 | MTF、场曲 / 畸变、波前、相对照度 | Zemax 分析结果的数值（`GetResults()` 的 DataSeries / DataGrid），报告绘制 |

规则：

- 所有图形都由交付轮次的验收模型生成（含参考筒镜、盖玻片设置，处于验收焦面），与逐项结果同一焦面。为使图形可读，在验收模型的副本上只保留 0、0.7、1.0 三个视场；剖面图只画到最后一个透镜面（虚拟光阑在其后、厚度为负，画到它会让光线往回折）。这些处理写在图注中。
- 只用 standalone 实例生成，不从窗口实例截图：同一镜头在窗口实例与后台实例上的数值相差约 10⁻⁵，拟合残差贴近界限时结论会翻转（step5-calibration.md 3.2 节）。
- 图注写明来源（"Zemax 原生导出"或"Zemax 计算，报告绘制"）、分析设置和单位。图形只帮助理解，判定以逐项结果为准。
- 显示哪些分析由系统需求决定：规格中有对应要求的（例如 MTF、照度均匀性）放在前面；没有要求的只作诊断量。
- 照度均匀性用序列模式的相对照度分析。杂散光需要非序列分析，第一版不评价，在"适用范围"中注明；序列模式的鬼像分析可作为诊断量。

接口实测（2026-10-13，OpticStudio 24.1.0，standalone，US4521083-e1 验收模型）：

| 内容 | 结果 | 耗时 |
|---|---|---|
| 2D 剖面 PNG（1400×700） | 成功 | 约 1.4 s |
| FFT MTF / 光线扇形 / 场曲畸变 / 相对照度（DataSeries） | 成功 | 0.03–1.0 s |
| 波前图（64×64 DataGrid，光瞳外为 NaN） | 成功 | 0.05 s |
| 分析窗口 `IA_.ToFile` | 导出文本列表，不是图片 | — |
| ZPL 宏导出分析图片 | 未测 | — |

模板示例：`%TEMP%/saos-acceptance-report-template.html`（结论数值虚构，图形取自真实验收模型）。

## 5. 文字与展示规则

- 结论只来自程序：只有全部判定项通过且评估有效时才写"通过"。
- 程序结论与 agent 解释在版式上分开；解释中引用的数值必须来自报告内已有的数据。
- 所有外部文字（用户原话、专利疑点、agent 解释）HTML 转义；没有脚本、远程资源、表单。
- 视觉规范沿用设计计划页面的浅色主题与字体；通过用青绿、未通过用红、假设用琥珀；视场与波长的曲线颜色和 Zemax 剖面图一致（蓝、绿、红）。宽表在自己的容器内横向滚动，支持桌面阅读和打印。

## 6. 命令（拟）

```bash
uv run saos report create --job <任务编号>   # 核对绑定后生成当前版本
uv run saos report show --job <任务编号>     # 当前版本路径、状态与校验值
```

## 7. 测试（拟）

通过、停滞、达到上限、无法评估四种状态各一份夹具；交付轮次选择（含 G 相同取较早者）；配置哈希、计划确认、镜头哈希不符时拒绝生成；未通过时差距报告出现且不出现"通过"字样；特殊字符转义；`report.json` 与页面数值一致。

## 8. 超出第一版范围时的说明

访谈中存在第一版验收器不能评价的要求时，不生成验收报告，而是生成一页范围说明：逐条列出这些要求、缺少的评价能力，以及已经可以评价的部分（如果有）。不得把不能评价的要求换成现有默认判据后给出"通过"。

以 光纤束侧视双光子镜头访谈记录（`work/native-fiber/jobs/20261014-100420-fiber-hemiellipsoid/sources/interview.md`） 为例，第一版验收器缺少的能力至少包括：

| 要求 | 缺少的评价能力 |
|---|---|
| 920 nm 激发焦点（约 1 µm 横向细节、轴向分辨能力） | 近红外单波长、有限共轭（光纤端面到组织内焦点）的点扩散函数评价；现有验收器固定为无限远、F′ / e / C′ 谱线 |
| 侧向折转与圆柱玻璃管壁 | 反射镜折转和非旋转对称的管壁像差建模；现有设计布局为序列旋转对称物镜 |
| 调焦与旋转过程中焦点大小、激发效率的均匀性 | 多位置（piezo 行程、旋转角）的一致性判据，需先约定允许变化量 |
| 荧光沿反向光路由整个光纤束端面收集 | 收集与耦合效率评价，需滤光片透射波段和荧光光谱 |
| 管内空气 / 液体两种版本 | 多配置比较 |

这类任务适合用来检验需求访谈是否正确识别超范围要求、是否没有静默套用默认值；它不能检验第一版"设计 → 优化 → 验收"的完整流程。
