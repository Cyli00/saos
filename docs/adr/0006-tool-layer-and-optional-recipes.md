# 从固定设计流程改为工具层加可选配方

zea 曾规定所有设计任务必须走同一条流程：访谈 → 从结构库选初始结构 → 设计计划确认 → 按规格差距和停机规则推进调整轮次 → 固定口径验收 → 报告。这套流程、规格格式、验收器和停机规则都按显微物镜写死，其中停机参数用 65 个基准任务也没能校准。要推广到其他光学系统，每一层都得重写，而且这些框架限制了 agent 按具体问题选择做法。因此项目改名为 saos，改为以需求到结果为导向：只保留需求框定这一个必经停顿，以及三条底线（记录需求原话和假设、交付数值有实测依据、不偷偷放宽需求）。工程重点放在通用的 ZOS-API 工具层和显性调试工具上，针对某类系统的做法写成配方，由 agent 在需求框定后按需加载。

## Considered Options

- 保留固定流程，按系统类型逐个扩展规格、验收和库：每个新类型都要先设计并校准整套框架，才能接第一个任务。
- 完全不设约束：agent 可能交付无法复核的数值，或者悄悄改小用户的要求。

## Consequences

- 显微物镜的规格、验收、轮次、结构库和优化基准代码原样移入显微物镜配方，只保证测试仍然通过。
- 不再测试 agent 的设计能力（优化基准、停机校准、模拟用户），只测试工具本身。
- 新配方只从实际完成的任务中提炼，不预先设计。
