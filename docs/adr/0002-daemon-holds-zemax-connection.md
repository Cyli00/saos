# 由常驻后台进程持有 OpticStudio 连接，命令行只做转发

实测（2024 R1，后台模式）每次新建 ZOS-API 连接要 4.4–5.6 s，而一个调整轮次需要调用多条命令。如果每条命令都独立启动 OpticStudio，单是启动开销每轮就要几十秒。因此由一个常驻后台进程持有连接，agent 仍然调用命令行，命令行只把请求转发给这个进程执行。这样 agent 看到的接口和"每条命令独立启动"的方案完全一样。

## Considered Options

- 每条命令独立启动 OpticStudio：最简单，但启动开销按命令数累加。
- 合并成粗粒度命令（一条命令完成一整轮）：只能减少启动次数，不能消除，而且命令的粒度会受这个限制。
- MCP 服务：同样是常驻进程，但会把接口绑定到 MCP 协议，命令行更容易测试，也能同时给 Claude Code 和 Codex 使用。
