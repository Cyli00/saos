## 1. 目标、保留项与完成边界

目标是减少返工和无效计算，同时使“当前能做什么、依据是什么、产物在哪里”有一个一致的答案。

固定方向：

- 同一个主会话连续承担需求、概念、结构选择和后续设计。阶段切换不以新开会话或交给子代理为默认实现。
- 前期唯一计算后端为 Optiland；用户认可报告及所选轮次后，才允许 ZOS 重建、核对和进一步优化。无自动 fallback。
- 概念先行，事实补齐、初筛、候选比较和深度优化分开。开放程度由实际工具配置与执行端控制、提示词不算权限隔离，这一条属于 R5，建议暂缓，待用户决定（见第 9 节）。
- 结构未指定时，起点从起点库按需求缩放并用一阶、三阶像差预判，候选由程序生成、不设配额；关卡只留在深度优化前和进入 OpticStudio 前，其余证据显示来源与是否过期（2026-10-21 用户改定，替代“至少比较三个候选”，见第 7 节）。
- 需求确认、模型确认、报告认可保留为三个用户确认；内部阶段凭产物推进，不额外增加逐阶段人工批准。
- 保留 Optiland 追迹、处方、材料计算、优化器、账本和现有 UI。按行为修复与合并，避免大范围改名、搬目录或重写物理内核。
- 原生快照是 Optiland 模型的权威文件；ZMX 是显式导出或最终 ZOS 阶段的原生文件。旧证据只读，不批量重写历史任务。
- 不扩张旧 Plan 4 的六模块工作台，不新建通用 agent 平台或 Node 前端构建链。

完成时必须分别给出：源码实现状态、静态检查结果、真实运行证据、宿主/许可证等阻断。任何一项未测，不写“通过”。

## 3. 实施顺序与责任边界

顺序：**R0 基线 → R1 文件与证据 → R2 ZOS 与会话 → R3 设计证据与关卡 → R4 材料与输入 → R5 主会话权限 → R6 数值与性能 → R7 迁移验收**。

宿主能力调查可在 R0 提前进行；R5 被宿主能力阻断时，不妨碍完成其他独立工作。数值正确性检查跟随每次优化相关修改，不等到 R6 才第一次测。工作流文档与 UI 在行为变化的同一批同步，R7 负责最后消除遗漏。

| 维护位置 | 唯一职责 | 调用方应停止做的事 |
|---|---|---|
| `lens_files.py` | 解析镜头产物、枚举真实文件、复制、替换、摘要与导出边界 | 自行用后缀、`exists`、glob 推断镜头是否存在 |
| `jobs.py` | 任务路径边界、证据封存及完整性检查 | 静默忽略必须封存但缺失的镜头 |
| `stages.py` | 阶段资格、证据依赖和允许操作的统一判定 | UI、报告、CLI 各自拼出另一套放行规则 |
| daemon / worker | 管理后端实例、执行授权操作、取消与恢复 | 用文件后缀或环境变量替代阶段认可 |
| 材料适配器 | 将有版本的数据转换为后端材料对象 | 只按同名牌号认定两份数据相同 |
| 技能 / UI / 报告 | 解释当前阶段、显示已有证据 | 决定权限，或为展示自动重算光学结果 |

接口名在实施时按现有调用方确定，不先建立通用框架。每项接口替换都同时迁移调用方并删除旧分支，不能只增加新接口、保留旧判断继续生效。

## 5. R1：统一镜头产物与证据保存

**改动范围**：`lens_files.py`、`jobs.py`、`backend/optiland.py`、`daemon.py`、`scripting.py`、`workflow.py`、`candidates.py`、`scan.py`、`parallel.py`、`report.py`、相关 CLI 与 UI 链接。

**怎么改**

1. 明确三类输入：Optiland 独立原生快照、旧式绑定双文件、最终 ZOS 原生镜头。新 Optiland 命令返回真实存在的原生路径；旧 `.zmx` 逻辑名称集中在解析边界兼容，不继续扩散虚拟路径。
2. 保存原生快照与导出 ZMX 分开。保存不再每次尝试导出；导出失败保留有效原生模型，并返回具体能力缺口。新增显式导出命令时同步帮助、技能、概览和图，不预先声称命令已存在。
3. 统一文件存在、重名、复制、删除、归档、全局搜索结果枚举及报告链接。覆盖判断检查整个镜头产物；拒绝时所有旧文件保持原字节。
4. 轮次必须封存全部权威镜头文件。必须存在的证据缺失应报错，不能由 `Job.seal` 跳过后照样追加账本。原生文件自身携带的哈希不能替代独立封存记录。
5. 新写入优先单文件原子替换；旧双文件更新/迁移保留备份和恢复策略。运行异常必须回滚；进程中断后允许明确报“不完整”并恢复，禁止把不完整文件当成成功快照。
6. 导出件和权威模型不要混用封存语义。历史绑定双文件仍严格校验；新显式导出保留来源摘要，后续修改导出件不能悄悄替换原生数据。
7. 保留旧归档和报告只读；迁移旧镜头时生成新副本并记录来源，不改封存哈希“消除告警”。

**查什么**

查所有 `LENS_SUFFIX`、`.zmx`、`is_file/exists`、`read_bytes`、`glob` 和 `seal` 调用，逐个标明属于原生模型、旧兼容还是最终 ZOS。特别检查候选输入、`GLOPT_*`、窗口捕获、失败轮次 orphan、worker 临时副本及公差报告的镜头摘要比较。

## 6. R2：修复 ZOS 接管、后端身份与恢复

**改动范围**：`daemon`、`stages`、`backend/zos.py`、`backend/baseline.py`、`demand`、`workflow`、`ledger`、`parallel`、`report`。

**怎么改**

1. 统一“校验认可来源 → 连接目标后端 → 捕获目标窗口未保存内容 → 加载/重建 → 提交阶段”的顺序。捕获明确针对即将被覆盖的 ZOS 实例，不能依赖当前 `self.backend` 恰好指向它。
2. 所有可触发后端切换的路径走同一入口，包括首次 `zos begin`、重启后的 load/build、脚本 load、换任务；窗口副本保存失败时禁止继续替换。
3. 每个后端实例维护自己的名称、版本、模式、精度与许可证信息。评估取实际执行后端；顺序与非序列 `system_info` 都提供一致身份字段，未知值明确为空，不能回退到另一个后端版本。
4. 将阶段入口分成可解释的准备、待复测、复测已记录、对比已封存状态，尽量由既有证据派生，不再额外维护多份布尔状态。
5. 未封存入口不能仅因 JSON 存在而授权。恢复时重新核对认可报告、所选快照、需求/checks 版本和确认记录，合法后才补封存；不把任意未封存文件补成用户认可。
6. 已记录 verify 的恢复复用该轮基准与材料证据；不重新计算冒充原值。新阶段预算以 verify 为基线，旧阶段停止/排除记录不能终止新阶段。
7. 后续报告只选本阶段合资格轮次。实际需求或结构改变时区分“正常优化变量变化”与“已认可前提失效”，由 R3 的证据规则决定返工范围。

**查什么**

查每个 `ZosBackend()`、连接、`New(False)`、`LoadFile`、`close`，标明授权来源、捕获时点、异常后的实例与镜头归属。查主实例和 worker 的后端切换及池锁，不让一个任务改变另一个任务的运行后端。

**测试**

| ID | 场景 | 通过条件 |
|---|---|---|
| Z01 | 无报告认可，走普通命令、环境变量、extension、worker 入口 | 标准入口不创建 ZOS；缺能力明确失败；任意脚本旁路的强隔离另按 R5 验收 |
| Z02 | 专用测试窗口已有未保存镜头，再首次进入和重启进入 ZOS | 重建前获得可重载副本；副本保存失败则原窗口内容不变；不连接用户窗口 |
| Z03 | 在连接、重建、入口写入/封存、verify 追加、对比写入/封存处中断 | 原参数重试只补缺项；成功入口仅有 1 条对应 verify；损坏证据不能被重新封存掩盖 |
| Z04 | 顺序/非序列、换任务、daemon 重启、worker 换后端 | backend/version 与真实实例一致；无 OpticStudio 0.6.3 这类串用；资源由所属任务正确使用 |
| Z05 | 两阶段不同上限、旧 stop/rule-out、checks rebase | 各阶段计数符合定义；只取消当前操作；旧停止与排除不泄漏到新阶段 |
| Z06 | 原 Optiland 的指标优于全部 ZOS 轮次 | 最终报告仍只选择合资格 ZOS 轮次；差异、未翻译设置和原认可版本可追溯 |

现有 `test_zemax_workflow.py` 和 `test_zemax_explicit.py` 仍含直接 `SAOS_BACKEND=zos` 的旧入口，应先迁移。窗口风险必须在自己启动的专用实例上真实检查，不能以 FakeBackend 通过代替。

## 7. R3：起点库、像差预判与诊断工具

2026-10-21 用户改定方向，本节替代此前“概念记录 + 至少三个手写候选 + 推翻条件 + 选择记录”的证据链。原因：那条链路的判断点都在防 agent 规避流程，每加一道关卡就多出可攻击的地方（同日 verifier 报出 9 项，其中 4 项属于对抗场景），却不能让起点变好；而脚本可以直接调用后端，防篡改本来就做不到完备。职业设计者的做法是：从已有设计取起点并缩放，按最吃紧的指标选形式，在追真实光线之前用一阶和三阶像差判断能否成立，用诊断手段决定加减元件，最后靠评审，不靠机械关卡（来源见第 7.4 节）。

### 7.1 原则

- **起点由程序系统地生成，不由 agent 凑数。** 候选来自起点库中的经典形式（按需求缩放），必要时再加光焦度符号的枚举；候选数不设配额。明显合适的形式可以直接用，但要在确认页写明最吃紧的指标和选型理由。
- **证据以可读的预判为主。** 每个候选给出一阶量、各面与合计的三阶（Seidel）像差、Petzval 半径与焦距之比、各面最大入射角；这张表就是选型依据，用户能看懂。
- **关卡只留在昂贵处。** 需求确认、模型确认、报告认可三个用户确认不变；硬关卡只有两道：深度优化前（需求已确认、当前模型已获确认）、进入 OpticStudio 前（报告认可）。其余证据不拦截，只显示“在哪个模型、哪个需求版本上算的，当前是否已不是那个版本”。
- **封存只用来发现意外，不作防篡改。** 不再为并发抢写、运行中改文件、检查脚本屏蔽警告这类对抗场景加机制。
- **诊断是工具，不是流程。** 临时非球面扫描和元件插入/删除扫描以库函数或固定命令提供，agent 按需调用，结果进确认页或报告。

### 7.2 改什么、怎么改

1. **起点库**：把显微物镜配方已有的初始结构库与专利适配（`library/microscope/entries/`、`src/saos/recipes/microscope/adapt.py`、`paraxial.py`）中通用的部分上收为核心库函数，按“代码上收”的规定前后数值一致。库条目记录：形式名、来源（书目或过期专利号）、适用视场与 f/#、片数、处方 JSON（参考焦距下）。先收少量经典形式（Cooke 三片、Petzval、Double-Gauss、远摄、反远摄、Cassegrain），有任务再加，不预先铺开。
2. **缩放**：按缩放规律（半径、厚度、口径、偏心乘 K；f/#、锥面系数、倾角不变；N 阶非球面系数乘 1/K^(N−1)）实现一个函数，供起点库和 agent 自写候选共用。
3. **像差预判**：Optiland 0.6.3 已有 `optiland.aberrations`（`SeidelAberrations`、`ThirdOrderAberrations`、`ChromaticAberrations`），先核对它与 OpticStudio 的口径是否一致，再基于它输出预判表；不另写三阶像差计算。
4. **初筛**：沿用 `saos scan` 的 candidates 计划。所有候选先零优化初筛，再用同样的短优化预算各跑一次；结论分为有效、预算内无效、未评估（材料、计算），保留“预算受限”标记和数值警告计数。按结构指纹去重。候选的 `hypothesis` 改为可选说明；去掉 `mechanism`、`risk`、`refuted_by`、`distinct_by` 的必填与相关结论规则。
5. **确认页的“选型依据”节**：改为显示最吃紧的指标、候选来源、像差预判表、初筛表，以及当前模型对应初筛中的哪个候选（按结构指纹匹配，匹配不上就写明）。不再读取 `selection.json`。
6. **深度优化关卡**：`workflow.require_optimise` 只检查需求已确认、当前模型已获确认，prescribed 结构的说明照旧显示；去掉 `require_selected` 和比较计数的放行条件。没有初筛记录时在确认页上警告，由用户决定。
7. **诊断工具**（可放在 R6 之后）：临时非球面扫描（在前、中、后各放一个低阶非球面并重新优化，报告各位置的贡献，再逐个去掉确认关键位置）；元件插入/删除扫描；初筛时可选的一阶公差灵敏度。
8. **结果指标**：`lens approve` 在结构指纹与上一次确认不同时，要求填写重建原因（例如“基础假设错误”“需求变了”）；报告中给出需求确认到首次模型确认、到报告认可的耗时。用于检验本方向是否减少返修。

|---|---|---|
| G01 | 起点库条目缩放到不同焦距 | 一阶量按缩放规律变化；非球面系数按 1/K^(N−1)；与解析值对照，容差先登记 |
| G02 | 像差预判表 | 小孔径小视场下与实际追迹一致；与 OpticStudio 的 Seidel 口径对照一次（认可后阶段或测试样本，不在前期启动 OpticStudio） |

## 12. 测试执行方式与交接格式

### 12.1 隔离和基准

- 所有 `saos` 命令使用 `SAOS_INSTANCE=verify`；检查并去掉可能覆盖它的 `SAOS_HOME`。集成夹具的任务根只允许在 `work/verify/`，纯函数/文件测试可以用独立临时目录。
