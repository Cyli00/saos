## 3. A：先收敛可靠性缺口

### A1. 查明非有限值警告

**改什么、怎么改**

- 从已出现 `invalid value encountered in matmul` 的路径提取最小可复现输入，保留镜头、材料、采样、优化参数及随机种子。
- 在测试或诊断入口中将该警告转为可定位的异常，追溯首个非有限值及其传播位置，不只停在最终矩阵乘法。
- 区分预期的无效光线与有效光线计算错误。前者应通过明确的有效性掩码及评价契约处理；后者修正计算或边界条件。不用统一替换 NaN 为 0、关闭警告或伪造有效结果解决。
- 检查失败步的状态恢复，保证最终保存的是合法模型。若局部屏蔽预期警告，必须限定范围，并保留无效光线的原因和数量。

**查什么**

追迹输入、面交点与方向、全反射/脱靶/遮挡处理、guard、评价函数、惩罚项、候选排序和保存。重点查保护性数值是否被误当成实测，以及无效步能否成为最终最优。

**测什么**

- N03：原警告样本；正常有效样本；全反射、脱靶、遮挡及求交失败代表样本。有效样本的评价结果有限，无效样本按既定契约处理，不能产生虚假的最优结果。
- N04：异常、取消、无改善和保存重载。失败后保留最后合法结果或回到约定起点，恢复后的评价与所保存模型一致。
- 将原警告样本保留为回归。报告警告来源、影响范围、修复前后结果，不能只报告“警告消失”。

### A2. 补文件证据的直接覆盖

**改什么、怎么改**

优先补齐遗漏的行为测试；发现实现缺陷再修。复用 `lens_files`、封存和来源检查，不在报告或 ZOS 入口另建一套文件判断。

**查什么**

**测什么**

- S03：对已封存快照分别删除和篡改，报告及 ZOS 认可路径明确拒绝；不得新增成功认可或成功阶段记录，也不得加载无效镜头。
- S06：旧绑定双文件迁移到新副本前后，原件字节摘要与原封存记录不变；新副本可加载并可追溯来源。
- 复用 `tests/test_lens_snapshot_files.py` 及相关工作流测试，避免只测底层函数而漏掉真实入口。

### A3. 恢复、阶段隔离和旧 ZOS 测试迁移

**改什么、怎么改**

- 先迁移共享测试夹具：经 Optiland 建模、模型确认、轮次及报告认可，再进入 ZOS。测试确认明确标识为自动化夹具，只用于 verify/临时任务。

- 若修复涉及阶段预算或最终报告选择，统一使用阶段归属和资格判定。

**查什么**

检查 `test_zemax_workflow`、`test_zemax_variables` 的两个失败项及 `test_zemax_e2e` 的夹具；查连接、窗口副本、加载、入口写入/封存、verify 追加、对比写入/封存的顺序。查旧 stop/rule-out、checks rebase 和阶段轮次计数的作用范围。

**测什么**

| 原编号 | 必须覆盖的行为 | 通过条件 |

| Z03 | 在连接、重建、入口写入/封存、verify 追加、对比写入/封存各点注入中断并重试 | 只补缺项；同一成功入口恰有 1 条对应 verify；不掩盖损坏证据 |

| Z06 | 所有 ZOS 轮次指标都不如 Optiland 轮次 | 最终报告仍只选择合资格 ZOS 轮次，同时保留两端差异及来源 |
| Z02 补充 | 自建专用 extension 会话含未保存内容，首次及恢复进入；副本保存失败 | 加载前获得可重载副本；副本失败时不替换；记录目标 PID 与所有权 |
| 旧测试迁移 | 4 个被旧入口阻断的测试 | 执行到原业务断言；后续失败逐项定位，不预设全部只是夹具问题 |

### B1. 材料身份从来源贯通到实际后端

**改什么、怎么改**

- 复用现有材料库和适配器，统一材料 ID、来源、数据摘要、公式/系数或表格、单位、适用波段及环境范围。
- 在实际 Optiland 材料对象、原生快照和报告之间保存一致的身份依据。读取旧快照不能默默换成材料库中最新的同名数据。
- 调研产物分别标记资料找到、数据完整、后端支持、实际加载。材料名字相同不能替代数据一致性。
- 仓库内维护材料调研规范；如需修改全局 `optic-material-explorer`，另列差异和作用范围，不夹带修改用户全局配置。

**查什么**

从材料调研记录追到 `MaterialStore`、实际 `DataMaterial` 或现有等价对象、快照及 ZOS 重建。核对已支持的 AGF 公式、Sellmeier/Cauchy、波长单位、温压参数、折射率约定和超范围行为。

**测什么**

- M01：每种已支持公式的有来源参考点；实际支持温度依赖的材料另测温度。运行前登记误差阈值及来源精度。
- M02：同名不同数据、缺色散、单位换算、超适用范围、库更新后重载。应明确拒绝或保持原版本，不能静默替换。
- M04：材料在原生保存重载和最终 ZOS 重建后仍可追溯；数值差异明确报告。

**范围建议**：无伴随 ZMX 导入继续明确拒绝，M03 暂缓到有实际导入需求时实施。该建议不等于 R4 全部完成；采用延期安排时，在总计划记录 M03 延期及影响。未来实现只接入可证明保真的子集，不另写完整 Zemax 解析器。

### B2. 起点库、缩放与像差预判

技术目标见综合计划第 7 节。本批先做 B0，再做 B2。

**改什么、怎么改**

1. **起点库**：先读 `skills/recipes/microscope/SKILL.md`、`src/saos/recipes/microscope/adapt.py`、`paraxial.py` 和 `library/microscope/entries/`，把其中与具体系统无关的部分（条目格式、按焦距缩放、近轴量）上收为核心库函数；上收前后用同一批条目对照数值，结果记入 `docs/recipes/microscope/`。在 `library/` 下新增通用起点库，先收 Cooke 三片、Petzval、Double-Gauss、远摄、反远摄、Cassegrain，每条写明来源（书目或过期专利号）、适用视场与 f/#、片数；`library/<库>/README.md` 写明来源、版本和用法。
2. **缩放**：一个函数实现缩放规律（半径、厚度、口径、偏心乘 K；f/#、锥面系数、倾角不变；N 阶非球面系数乘 1/K^(N−1)），起点库和 agent 自写的处方共用。
3. **像差预判**：基于 `optiland.aberrations` 的 `SeidelAberrations`、`ThirdOrderAberrations`、`ChromaticAberrations` 输出每个候选的预判表：一阶量（EFL、BFL、总长、光阑与光瞳位置）、各面与合计的三阶像差、Petzval 半径与焦距之比、各面最大入射角。先核对这些量的符号与归一化约定，不另写三阶计算。
4. **从需求生成候选**：按需求中最吃紧的指标（视场、f/#、波段）从起点库筛出适用形式，缩放后写成 candidates 计划。生成方式写成库函数，由 agent 调用；程序生成的候选自动带上形式名和来源。光焦度符号枚举（DSEARCH 式）放到第二步，等真实任务表明库里的形式不够时再做。
5. **初筛**：所有候选先零优化初筛，再用同样的短优化预算各跑一次。结论分为有效、预算内无效、未评估（材料、计算），保留预算受限标记、数值警告计数和结构指纹去重。

**查什么**
