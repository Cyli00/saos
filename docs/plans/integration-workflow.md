## 3. 拟实现工作流与契约

主线：**需求与计算安排确认 → 起点生成或原生镜头加载 → 模型确认 → 所选后端优化 → 必要的后端交接与复测 → 报告交付**。

### 3.1 需求确认与路径选择

| 输入/任务 | 拟选路径 | 边界与输出 |
| --- | --- | --- |
| 从零设计，Optiland 能表达的系统 | Optiland 生成、预判、初筛；最终需要 Zemax 交付时，模型确认后可转 ZOS 深度优化 | 写明候选来源、库适用范围、未评估原因、主优化后端与预算 |
| 已有 Zemax 镜头，主要任务是改进设计 | 在需求确认的计算安排内直接使用 ZOS 加载与建模 | 保护原文件；不强制转成 Optiland 后再转回；深度优化仍需模型确认 |
| 含 Optiland 不支持的面型、配置、材料或判定 | 在需求确认时明确 ZOS 路径 | 无资源则报告阻断；不静默删字段、简化模型或转后端代算 |
| 用户只需要受支持的 Optiland 探索结果 | 在 Optiland 内完成有限范围探索与报告 | 明确未经 OpticStudio 验证，不冠以最终 Zemax 交付 |

路径选择只使用任务需求和可核实的能力信息，先复用现有能力检查，不建设自动推测最快后端的通用调度器。后端、允许操作和预算纳入确认内容；超出确认范围的后端使用要重新取得相应授权。

### 3.2 起型、初筛与模型确认

- 自由结构从有来源的库条目生成，严格筛选与外推明确区分；零候选返回原因，不无限重试，也不为凑数生成候选。
- 先零优化初筛；短优化仅在能力支持、评价定义有效且预算明确时执行，同组候选采用同预算。配置错误、材料缺失、计算错误和预算内无效分别记录。
- 确认页复用已生成的来源、预判和初筛证据，同时显示拟用主后端与未验证项；无初筛记录保留警告，不新增候选配额或选择文件关卡。
- 需求与模型确认继续作为深度优化前置条件。结构与环境声明变化按既有指纹规则重新确认；普通变量调参、新测量和展示刷新不触发重复确认。

### 3.3 深度优化与资源

- 最终需要 Zemax 交付的任务优先用 ZOS 原生优化能力；复用已有局部优化、搜索、玻璃目录限制和 worker 生命周期。
- 已选用 Optiland 的任务保留受支持算法、预算和恢复；无接受步、无改善、到期和收敛分别报告，不因未改善自动跨后端重试。
- 两类 worker 按实际后端管理，候选互相隔离；许可证预算包含用户窗口，CPU/GPU 资源设置留出用户交互余量。
- 预算包含约定的测量、复核和归档；清理阶段必须可恢复最后已验证模型。原生调用无法保证硬实时的边界明确披露，不能把 Python 检查点当成进程崩溃保护。
- 后端转换和重试不隐式赠送额外轮次或时间。新阶段预算从已确认安排取得；旧任务仍按其原阶段规则解释。

### 3.4 Optiland → ZOS 交接

输入为选定的有效快照、需求/判定版本、模型确认及后端使用授权；**拟取消“Optiland 必须先达标并形成获认可报告才能进入 ZOS”的依赖**。交接可以发生在模型确认后，也可发生在预算内探索结束后。

处理顺序：核对输入及封存 → 连接目标实例 → 保护将被替换的窗口内容 → 从快照处方重建 → 核对设置和材料 → 用相同需求定义记录 ZOS 基线与差异 → 提交阶段 → 允许深度优化。

| 必须保持的含义 | 失败与恢复契约 |
| --- | --- |
| 几何、面型、非球面阶数、光阑与口径、视场与波长、材料数据、配置/环境、变量与评价定义 | 不能翻译的项逐项报告并阻止把交接记成成功；不得静默取默认值 |
| 材料身份 | 记录来源、数据版本、单位和有效范围；同名不同数据不能自动视为等价，差异必须可追溯 |
| 光学数值 | 区分模型翻译错误和两个后端的数值差异；前者阻断交接，后者按预登记比较口径记录，不能直接认作优化改善 |
| 原模型与用户窗口 | 保存副本失败时不覆盖；异常不丢失唯一有效快照；重试复用同一交接依据，不重复新增成功基线 |

以 ZOS 基线开始后续轮次，正常优化不往返切换后端。直接 ZOS 路径记录自己的首轮基线，不伪造 Optiland 对照数据。

### 3.5 报告与迁移

报告分别给出流程完成、优化改善、需求达标、实机验证状态，并标注各指标的实际后端。不同后端的 merit 不拼成可直接比较的下降曲线；最终 Zemax 交付只选合资格的 ZOS 镜头和指标。

旧 `.optiland.json`、绑定双文件、ZOS 原生文件及封存保持兼容；读取旧阶段记录不能自动授予新的后端权限。旧任务继续采用原认可语义；转入新路径须显式记录迁移依据，不重写旧确认、预算或封存来掩盖差异。

## 4. 与既有决定的关系

| 既有规则 | 本计划拟调整 | 实施要求 |
| --- | --- | --- |
| 前期唯一后端为 Optiland；报告认可后才启动 ZOS | 需求确认时明确后端安排，支持直接 ZOS；Optiland 未达标也可在授权范围内交接 | 同批修改 `stages`、daemon/worker 入口、技能、UI、图和帮助，更新 DESIGN 与 ADR-0012 的生效关系 |
| 进入 ZOS 时重新给阶段轮次上限 | 新路径按确认的阶段预算执行，转换不自动重置 | 保留旧任务解释，明确新旧记录的兼容规则与取消/重试行为 |
| Torch 优先，用不了才回退差分 | 保留 Optiland 内部选择规则；不再以它承担所有任务的深度优化 | 不将算法回退与整任务后端选择混为一谈 |
| 深度优化前确认、结构变化再确认、最终 ZOS 实测依据 | 保留 | 新入口不能省略需求/模型确认，不能把探索报告当成已验证交付 |

整理计划本身不修改上述运行规则。实施前应把确认内容、状态输入输出、失败语义和旧任务迁移方式写入同一批可审查改动；不能仅恢复旧环境变量直启 ZOS 来绕过新工作流。

## 6. 验收范围与停止扩测条件

实现与测试继续按用户分工交接。本计划只规定待验证行为；本次运行测试为 0。测试环境与进程所有权遵循 [AGENTS.md](../../AGENTS.md)。

| 验收组 | 必须取得的证据 | 边界 |
| --- | --- | --- |
| V1 新旧路径与权限 | 新直接 ZOS、Optiland 起型后交接、旧任务继续工作的代表路径；缺需求/模型确认、缺授权、重启/重试、阶段预算 | 每条只验证受本次改变的契约；任意 Python 脚本的强隔离不列为本次交付 |
| V2 转换与恢复 | 来源/材料/设置核对，真实 ZOS 首轮基线；错误输入不部分成功；窗口副本、取消、超时、异常、保存重载 | 替身可验证错误分支，但不能替代真实光学数值或窗口保护；用自建测试实例 |
| V3 优化与报告 | 一条从零起型转 ZOS 路径、一条已有 ZOS 镜头路径；未达标起点、有效改善、重载一致、报告来源明确 | 固定输入、评价与预算；不以起点本来达标代替优化验收，不测 agent 设计水平 |
| V4 工作流同步 | 受影响回归、四处语义检查、相关 UI 状态中英文浏览器检查、drawio 渲染 | 图渲染已包含命令同步检查时不重复跑；真实 ZOS、浏览器、CUDA 结果分别记录 |

验收数值容差、允许的预算超额和样本输入须在运行前登记，并来自需求或已知数值精度。先定向检查，最后对整合版本做一次适用回归；通过后仅因新改动、新失败或未解问题补测，不反复跑全套。

性能不设未经证明的倍数目标。执行上述必要路径时顺带记录总耗时和优化/交接耗时；若要与旧 `saos` 分支比较，应保持镜头、采样、评价与预算一致，明确冷/热状态和样本数。没有成对测量时不宣布加速，也不为填表单独展开 CUDA 或多算法竞赛。

Optiland 梯度验收只在启用相应路径时补齐：保留原 F01 失败结果，在光滑有效区域检查多个扰动尺度的收敛，结合绝对/相对误差和边界方向登记判据；不让 AD 拟合粗步长差分，也不以单一小步长通过替代覆盖。
